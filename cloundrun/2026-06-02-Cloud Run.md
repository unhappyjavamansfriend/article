# 驗證

允許公開存取
系統不會執行驗證檢查。

需要驗證
請選取 Identity and Access Management (IAM) 和/或 Identity-Aware Proxy (IAP)。

**「誰有資格透過網址連到這台 Memos 網頁伺服器？」**

這裡的正確答案是：**請選擇「允許公開存取 (Allow unauthenticated invocations)」**。

## 為什麼要選「允許公開存取」？

這聽起來有點反直覺（畢竟我們之前一直強調隱私和安全），但這裡的「公開存取」指的是**網頁外門**，而不是你裡面的日記資料。原因如下：

1. **讓網頁可以正常顯示**： Memos 本身是一個完整的 Web 應用，它**自帶**全套的密碼登入、權限控管與帳號註冊系統。為了讓你的手機 App、瀏覽器可以連到它的「登入畫面」，你必須讓 Cloud Run 的網址對外公開。
    
2. **與之前的「禁止公開存取儲存桶」不衝突**：
    
    - 之前的 **Cloud Storage (Bucket)**：那是金庫（硬碟），必須**完全禁止公開**，只有拿著金鑰的 Memos 後端程式才能進去讀寫。
        
    - 現在的 **Cloud Run (Memos)**：這是門面的守門員。你讓守門員公開站在大門口（允許公開存取網址），別人才有機會來到登入介面，輸入帳密後，由守門員進去金庫幫你拿資料。
        

如果這裡選了「需要驗證」，那連 Memos 的登入畫面都還沒看到，GCP 官方的 IAM 防火牆就會直接把你的瀏覽器擋在外面，連你自己都無法訪問。

## 這樣安全嗎？

**非常安全。** 因為當你部署完成並第一次打開網址時，Memos 會強迫你註冊第一組帳號。這組帳號就是 **最高管理員**。

註冊完後，你可以立刻進入 Memos 的 **「設定 (Settings)」➔「系統 (System)」** 中，將「允許訪客註冊 (Allow users to sign up)」的功能**關閉**。這樣一來，外面的路人就算知道你的 Cloud Run 網址，他們也只能看到一個冷冰冰的登入框，既不能註冊、也看不到你的任何私密筆記。

所以，請放心勾選 **「允許公開存取」**，然後就可以繼續往下滑，展開底下的「組態、安全性、磁碟區」去改 Port (5230) 和掛載儲存桶囉！


# 帳單

以要求為依據

只有在處理要求時才會收費。如果沒有要求，CPU 就會受到限制。

以執行個體為依據

針對執行個體的整個生命週期收費，各執行個體可全程完整使用 CPU。



**「你想用哪種算力模式來付費？」**

這裡的黃金組合是：**請選擇「以要求為依據 (Request-based)」**。

這是 Cloud Run 最精髓、也是它身為 **Serverless（無伺服器）技術能幫你極致省錢**的核心原因。以下幫你拆解這兩種模式在「荷包」與「體驗」上的巨大差異：

## 兩種計費模式大拆解

### 1. 以要求為依據 (Request-based) ⭐ **強烈推薦**

- **白話解釋**：**「有流量才收費，沒流量免費。」** 只有當你打開手機或電腦、對 Memos 發起點擊、寫日記（有 HTTP 請求）的那幾毫秒或幾秒鐘，GCP 才會開始精準計算 CPU 和記憶體的消耗並收費。
    
- **省錢威力**：當你關掉網頁、去睡覺、或是上班沒在用 Memos 時，Cloud Run 會直接把容器縮容到 0。**此時算力收費是完全的 0 元！** 對於個人日記、輕量記帳、甚至是幾十個人的朋友小社群，這種模式通常能讓你每月的帳單**趨近於 0 元**。
    
- **唯一小缺點**：如果一陣子沒人連線，當你下一次突然打開網頁時，容器需要重新開機，你會感覺到網頁大概轉圈圈「冷啟動（Cold Start）」2~3 秒。但之後的點擊就會恢復絲滑。
    

### 2. 以執行個體為依據 (Instance-based)

- **白話解釋**：**「傳統 VM 包月模式。」** 容器會 24 小時不間斷地在 GCP 後台待命，維持完整的 CPU 算力。
    
- **缺點**：不論你有沒有在寫日記，只要這台容器亮著，GCP 就會像開著冷氣一樣按時對你收費。雖然一個人用，每個月可能也就幾百塊台幣，但這就失去了玩 Serverless 的極致省錢樂趣。
    
- **適合場景**：企業級的核心商業專案，絕對無法容忍那 2 秒鐘的冷啟動，或者每天 24 小時都有成千上萬的龐大流量在轟炸。
    

## 最佳實踐操作

1. 毫不猶豫點選 **「以要求為依據 (Request-based)」**。
    
2. 接下來，請確認好你之前設定的這兩項，它們是 Request-based 的絕配防線：
    
    - 剛才在上方設定的 **「最小實例數」必須是 `0`**（這樣沒人連時才能真正歸零省錢）。
        
    - **「最大實例數」必須是 `1`**（保護 SQLite 資料庫不被並發寫入鎖死）。


# Ingress

內部

允許從自有專案、共用虛擬私有雲和 VPC Service Controls 範圍傳出的流量，**從其他 Cloud Run 服務傳出的流量必須透過虛擬私有雲轉送**。須遵守限制。[瞭解詳情](https://cloud.google.com/run/docs/securing/ingress?hl=zh_TW) 

允許外部應用程式負載平衡器傳出的流量

全部

允許直接從網際網路存取服務


進階設定的網路區塊「Ingress (傳入流量)」了，這裡 Google 是在問你：**「你想讓外部的人透過什麼『路徑』連進你的 Memos？」**

結論直接給你：**請選擇「全部 (All) - 允許直接從網際網路存取服務」**。


## 為什麼要選「全部」？

這個設定決定了你的 Memos 網頁大門面向哪裡：

1. **直接拿到對外公開網址**： 選了「全部」之後，Cloud Run 部署完成會直接發配給你一組全球通用的 `https://xxx.a.run.app` 網址。不論你在公司、在家裡，還是出門在外用手機 4G/5G 網路，只要輸入這串網址，就能直接連回你的 Memos。
    
2. **其他選項是給企業內網用的**：
    
    - **內部 (Internal)**：這會把網頁完全封鎖在 Google 的虛擬私有雲（VPC）內。通常是公司的微服務後端（例如 A 服務要呼叫 B 服務）才會選這個，選了這個的話，你的瀏覽器或手機是完全連不進去的。
        
    - **允許外部應用程式負載平衡器...**：這代表網頁前面必須再架設一組 GCP 的 Load Balancer（負載平衡器）當作唯一入口。雖然架構更龐大、更安全，但每個月會多出幾百到上千元台幣的負載平衡器固定帳單，對於個人自建來說太奢侈了。

# 容器

關於「容器大腦運作效能」**與**「並發處理能力」的微調


**容器通訊埠 (Container Port)**：改為 **`5230`**（Memos 預設埠）。

## 1. 什麼是並行（Concurrency）？

- **白話解釋**：**「這台容器同時能一心多用到什麼程度？」**。
    
- **舉個例子**：如果設定「並行數量上限為 80」，代表當有 80 個人同時在刷你的 Memos 動態、寫日記時，**同一台** Cloud Run 容器可以同時處理這 80 個人的請求。直到第 81 個人連進來，GCP 才會考慮要不要開下一台容器（但因為我們之前把最大實例鎖定在 1，所以第 81 個人會排隊等前面的空位）。
    
- **建議配置**：維持預設值（通常是 80）或不用改它。Memos 的後端是用 Go 語言寫的，Go 天生具備極強的高並發處理能力，一邊應付幾十個人同時連線完全是小菜一碟。
    

## 2. 要求逾時（Timeout）

- **白話解釋**：**「網頁轉圈圈多久沒反應就要斷線報錯？」**
    
- **建議配置**：維持預設的 **`300 秒`**（5分鐘）。因為 Memos 只是傳輸文字和幾張照片，幾毫秒就處理完了。除非你上傳好幾 GB 的超大影片，否則不需要動它。
    

## 3. 執行環境（Execution Environment）【關鍵，請選第二代】

- **白話解釋**：這是 Google 提供給容器底層的 Linux 內核架構。
    
- **建議配置**：**請務必手動勾選「第二代 (Second Generation)」**。
    
- **為什麼？**：因為我們使用了 **Cloud Storage FUSE（掛載 Bucket 當硬碟）** 的高階功能。第一代執行環境對虛擬檔案系統的支援度較低，**只有第二代環境才能完美、絲滑地支援網絡檔案系統與 FUSE 掛載**，同時還能帶來更快的 CPU 寫入效能。
    

## 4. 啟動時 CPU 效能強化（CPU Boost）

- **白話解釋**：**「開機時要不要打類固醇？」**
    
- **建議配置**：**勾選啟用**（預設通常是勾選的）。
    
- **為什麼？**：因為我們採用了 Request-based（沒流量就縮容到 0）的省錢模式，當有人連線需要「冷啟動」時，啟用這個功能可以讓 GCP 在開機的前幾秒鐘，**免費塞給你雙倍的 CPU 算力**，把開機轉圈圈的時間從 5 秒縮短到 1.5 秒，大幅提升你打開日記本時的流暢體驗。
    

## 5. Cloud SQL 連線

- **白話解釋**：這是用來直接連線 GCP 託管型資料庫（PostgreSQL/MySQL）的快速通道。
    
- **建議配置**：**留空，完全不用勾選**。因為我們目前是把 SQLite 資料庫存在剛剛建好的 Cloud Storage（Bucket）裡，沒有用到 Cloud SQL。

# 磁碟區

## 補掛硬碟

- 切換到 **「磁碟區 (Volumes)」** 分頁（通常在第二或第三個標籤）。
    
- 點擊 **「新增磁碟區 (ADD VOLUME)」**：
    
    - 磁碟區類型選擇：**Cloud Storage 儲存桶**。
        
    - 儲存桶名稱：下拉選取你之前建好的 **Memos 專用 Bucket**。

- 往下滑一點點，看到 **「容器掛載項目 (Container Mounts)」**：
    
    - 掛載路徑精準輸入： `/var/opt/memos`

- 直接拉到頁面最下方，點擊藍色的 **「部署 (DEPLOY)」** 按鈕！

### Bucket 全部賦予


Cloud Run 服務身分可能不具備必要權限，無法存取這個 GCS bucket。如要減少可能發生的錯誤，您可以授予下列角色：
針對 xxx-runner@my-project-12345-memos.iam.gserviceaccount.com：
roles/storage.objectUser on my-xxx-data-bucket 



「防呆檢查」。它的意思是：你雖然在 Cloud Run 裡指定了要掛載這個 GCS Bucket（硬碟），也指定了要用 `memos-runner` 這個身分（執行官）來跑，但你還沒有在大門口的 IAM 權限系統裡，把**進入這個金庫（Bucket）的鑰匙**真正發給這位執行官。

### 為什麼要賦予 `roles/storage.objectUser`？

- **這是 Memos 的核心命脈**：Memos 的所有筆記、SQLite 資料庫、以及你上傳的照片，全部都要寫進這個 Bucket 裡。
    
- **精準的最小權限原則**：`storage.objectUser`（儲存空間物件使用者）這個角色非常安全。它只允許 `memos-runner` 對這個 Bucket 裡面的**檔案**進行「讀取、寫入、刪除」，但**不允許**它去刪除整個 Bucket 或是更改別人的權限。

## 唯讀

對不要勾！請務必保持「取消勾選」（不勾）的狀態。

1. **Memos 需要在裡面寫入資料庫**： Memos 是一個「動態」的日記系統，當你寫下第一則筆記、註冊管理員帳密時，它必須把這些資料寫入 `memos_prod.db` 這個 SQLite 資料庫檔案裡。如果勾了唯讀，Memos 就沒辦法寫入帳密，你連第一步註冊都無法完成。
    
2. **你以後要上傳照片和檔案**： 唯讀代表這個儲存桶只能看、不能動。你以後用手機 App 拍的照片、隨手記下的心得，都會因為「禁止寫入」而被擋在門外。
    

## 正確的邏輯是：

- **對網際網路（外面的陌生人）**：我們之前已經設定了「禁止公開存取」，所以外面的駭客完全看不到、也連不進這個 Bucket。
    
- **對 Memos 程式本身（`memos-runner`）**：它必須擁有**讀取+寫入**的完整權限（也就是剛才賦予的 `objectUser`），它才能流暢地幫你存取日記。


# image

Cloud Run 的控制中樞（Control Plane）都會自作聰明地執行一條安全規則：_「只要是 Docker Hub，就自動重寫成 `mirror.gcr.io` 幫用戶加速。」_ 但偏偏 Google 的這個官方鏡像站老舊失修，裡面根本沒有 Memos，導致無限 Image not found。

需要Cloud Build，在內網拉取 Memos、打包

## 確保 Cloud Shell 切換到正確的專案

```bash
gcloud projects list

PROJECT_ID: my-project-30027-memos
NAME: My Project 30027 Memos
PROJECT_NUMBER: 946737187936


gcloud config set project [PROJECT_ID]
```
## 建立一個 Dockerfile

直接用這段指令在資料夾內建立 Dockerfile，內容直接對接 GitHub 官方最新版：

```bash
mkdir memos
cd memos

cat > Dockerfile <<EOF
FROM ghcr.io/usememos/memos:latest
EOF
```

## 啟用必要 API

```bash
gcloud services enable \
  cloudbuild.googleapis.com \
  artifactregistry.googleapis.com \
  run.googleapis.com
```

- `cloudbuild.googleapis.com`（負責幫你下載並編譯 Dockerfile）
    
- `artifactregistry.googleapis.com`（負責存放打包完的映像檔）
    
- `run.googleapis.com`（負責把網頁跑起來）

## 使用 `--source .`（原始碼部署）

```bash
gcloud run deploy memos \
    --source . \
    --region=asia-east1 \
    --port=5230 \
    --execution-environment=gen2 \
    --service-account=memos-runner@my-project-30027-memos.iam.gserviceaccount.com \
    --max-instances=1 \
    --allow-unauthenticated
```
