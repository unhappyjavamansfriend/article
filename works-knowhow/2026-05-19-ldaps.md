​假設你的 Java 程式碼寫著要連線到：ldaps://company.local:636
# 1. 域名解析（找 IP）

​Java 啟動連線，發現目的地是網域名稱 company.local。
​Java 會先去查作業系統的 本地 hosts 檔案。
​如果 hosts 寫著 192.168.10.50 company.local，Java 就成功拿到了 IP 192.168.10.50。（如果 hosts 沒有，才會去問內網的 DNS 伺服器）。

# 2. 建立 TCP 連線（敲門）

​Java 拿著剛剛找到的 IP 和 Port 636，在網路上正式發送封包給那台 LDAPS 伺服器，建立最底層的 TCP 連線。此時就像是 Java 走到伺服器門口敲門說：「哈囉，我想建立安全連線。」

# ​3. 開始 TLS 握手（Client Hello）

​此時「TLS 握手」正式開始！
Java 向伺服器發送 Client Hello 封包，告訴伺服器自己支援哪些加密演算法。

# ​4. 伺服器出示憑證（Server Hello + Certificate）

​LDAPS 伺服器回應 Server Hello，並且把自己的數位憑證（包含公鑰）打包丟給 Java。

# ​5. Java 驗證憑證（信任庫與名稱比對）—— 關鍵就在這！

​Java 收到憑證後，暫停接下來的資料傳輸，開始進行你提到的嚴格檢查：
​檢查發行機構： Java 翻開自己的信任庫（cacerts），看看這張憑證的簽發者（CA）是不是在信任名單裡。

​檢查域名（CN 比對）： Java 檢查憑證上寫的 CN=company.local，是不是跟當初程式碼輸入的 company.local 一模一樣。

​⚠️ 如果驗證失敗： 只要上述其中一項不通過（例如信任庫找不到、或是 CN 名字對不起來），Java 就會立刻中斷握手，直接拋出 SSLHandshakeException 或 PKIX path building failed 錯誤，連線宣告失敗。

# ​6. 完成握手（交換對稱金鑰）

​如果憑證驗證完全通過，Java 就會產生一組隨機的「對稱金鑰」，用憑證裡的公鑰加密後傳給伺服器。雙方確認無誤後，TLS 握手宣告正式完成。

# ​7. 傳送 LDAP 資料（例如帳密驗證）

​握手完成後，安全通道已經建立。Java 這才開始把真正的 LDAP 請求（例如員工的帳號、密碼，或是查詢指令）用剛才的對稱金鑰加密並送過去。
