# oracle 建庫

- **`CREATE DATABASE`** > **千萬別做**，那是 DBA 在作業系統層級裝機時才在玩的。
    
- **`USE DATABASE`** > **Oracle 沒有這玩意**。
    
- **正確做法**：**「一個專案 ＝ 一個 Oracle 帳號」**。在 DBeaver 裡用哪一個專案的帳號登入，你當前就在哪一個專案的資料庫空間裡！
- 

## 建立或修改 DBeaver 連線

在 DBeaver 左側邊欄，對著你的 Oracle 連線點擊 **右鍵 > 編輯 連接 (Connection Settings)**。

## 切換為最高管理員 `SYS` 帳號（關鍵 ）

1. 將 **使用者名稱 (Username)** 改為：**`sys`**
    
2. 輸入你當初建立 Oracle 容器時設定的 `SYS` 密碼（如果是官方預設鏡像，可能是 `Oradoc_db1` 或你在 `docker-compose.yml` 裡設定的 `ORACLE_PWD`）。
    
3. 最重要的一步 ：尋找一個叫做 **「角色 (Role)」** 的下拉選單（通常在帳號密碼欄位的附近）。
    
    - 預設是 `Normal`。
        
    - **請務必將它切換為 `SYSDBA`**。 _(在 Oracle 中，登入 `sys` 帳號如果沒有指定 `SYSDBA` 角色，一樣會被拒絕連線或噴權限不足)_。


## 建立專案專用帳號

```sql
-- 1. 順利建立專案專用帳號 (如果是在 12c 以上的容器，帳號開頭可能要加 C##，例如 C##UNCLEREAL)
CREATE USER UNCLEREAL IDENTIFIED BY YourSecurePassword123;

-- 2. 賦予專案常規權限
GRANT CONNECT, RESOURCE, DBA TO UNCLEREAL;

-- 3. 允許該帳號無限使用資料夾空間
ALTER USER UNCLEREAL QUOTA UNLIMITED ON USERS;
```

執行完後的下一步：換回專案帳號

當你用 `sys` 帳號幫專案把 `UNCLEREAL` 帳號和權限都設定好之後：

1. 請在 DBeaver 建立一個**全新的連線**。
    
2. 這次的使用者名稱填入 **`UNCLEREAL`**，角色選回 **`Normal`**。
    
3. 連進去後，就可以開始跑建表腳本了！

# oracle 建表

## 權限

**如果查得到資料（顯示 `CREATE TABLE`）**：代表你這個帳號已經擁有直接建表的權限。
```sql
SELECT PRIVILEGE 
FROM USER_SYS_PRIVS 
WHERE PRIVILEGE = 'CREATE TABLE';
```

## 「透過角色繼承的權限（Role Privileges）」

有時候權限不是直接給你的，而是包在像 `RESOURCE` 或 `DBA` 這種「角色（Role）」包包裡塞給你的。請執行這段查詢：
```sql
SELECT ROLE, PRIVILEGE
FROM USER_ROLE_PRIVS ur
JOIN ROLE_SYS_PRIVS rs ON ur.GRANTED_ROLE = rs.ROLE
WHERE rs.PRIVILEGE = 'CREATE TABLE';
```
- **如果你看到 `RESOURCE` 或者是 `DBA` 對應著 `CREATE TABLE`**：代表你透過角色間接擁有了建表能力。
    
- **如果這裡也查不到任何資料**：那就百分之百確定，目前這個用戶身上**完全沒有任何可以建表的權限**！

## 空間的使用權

在 Oracle 裡，沒有硬碟空間的使用權，一樣會被當成「權限不足（insufficient privileges）」
```sql
-- 請用 sys 帳號執行（用戶名，必須維持大寫）
SELECT TABLESPACE_NAME, USERNAME, BYTES, MAX_BYTES
FROM DBA_TS_QUOTAS
WHERE USERNAME = 'UNCLEREAL';
```

- **如果 `MAX_BYTES` 顯示 `-1`**：代表 `UNLIMITED`（無限額），這是最完美的狀態，代表硬碟空間絕對沒被卡住。
    
- **如果 `MAX_BYTES` 顯示 `0`**：代表被明確禁止寫入。

## 確認帳號

```sql
SELECT USER FROM DUAL;

SELECT SYS_CONTEXT('USERENV', 'CURRENT_SCHEMA') FROM DUAL;
```

如果這個印出來的名字跟上面的 `USER` **不一樣**，代表你的 DBeaver 工具在背後自作聰明地幫你切換了環境（Current Schema）。這會導致你直接輸入 `CREATE TABLE abc` 時，Oracle 以為你要去別人的地盤建表，因而引發權限不足。

```sql
-- 將當前視窗的 Schema 強制切換回你自己的帳號 （用戶名，必須維持大寫）
ALTER SESSION SET CURRENT_SCHEMA = UNCLEREAL;
```
